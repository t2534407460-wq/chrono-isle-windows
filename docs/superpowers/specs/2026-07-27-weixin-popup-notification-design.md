# 微信桌面通知同步设计

## 背景

当前灵动岛通过 Windows `UserNotificationListener` 接收系统通知。QQ 会注册并写入 Windows 通知中心，因此可以正常同步；当前桌面微信 `D:\Weixin\Weixin.exe` 使用自己的右下角通知窗口，通知不会出现在 `Win + N` 通知中心，现有系统通知监听无法获得它。

## 目标

- 微信自有通知窗口出现时，将发送者和消息摘要同步到现有灵动岛通知横幅。
- 保持 QQ 和其他 Windows 系统通知的现有行为。
- 仅在“收纳新的 Windows 通知，并在灵动岛显示 5 秒”设置开启时监听。
- 不读取微信聊天数据库，不注入或修改微信进程。

## 方案

新增独立的微信窗口通知捕获组件：

1. 使用 `SetWinEventHook` 监听桌面窗口的显示和名称变化事件。
2. 仅处理进程映像名为 `Weixin.exe` 的窗口，忽略微信主窗口和不可见窗口。
3. 使用 UI Automation 读取通知窗口中可访问的文本节点，过滤按钮、固定提示和重复文本，组合为发送者与消息摘要。
4. 对短时间内相同的发送者和内容进行去重。
5. 将结果转换为现有 `SystemToastMessage`，通过 `SystemToastInboxService.ToastReceived` 进入原有灵动岛显示、5 秒隐藏和吸附布局逻辑。
6. 服务停止或应用退出时解除 WinEvent 钩子，避免遗留回调。

如果当前微信版本的通知窗口不公开任何 UI Automation 文本，则保留诊断日志并停止在窗口捕获层，不引入 OCR、数据库读取或进程注入等扩大范围的替代方案。

## 组件边界

- `WeixinPopupNotificationSource`：负责窗口事件、微信进程过滤、UI Automation 文本提取和生命周期。
- 纯逻辑辅助类：负责文本规范化、通知窗口判定与去重，便于单元测试。
- `SystemToastInboxService`：继续作为统一入口，启动和释放微信通知源，并转发现有 `ToastReceived` 事件。
- `LifeIslandWindow`：不新增微信专用逻辑。

## 测试与验收

- 单元测试先覆盖微信进程过滤、文本组合、噪声过滤和短时去重。
- UI 契约测试确认微信通知源接入现有通知服务并随其释放。
- 运行全部核心测试和 UI 契约测试。
- 覆盖 win-x64 自包含测试版并重新启动。
- 手工发送一条微信消息，确认灵动岛显示发送者和摘要，5 秒后按当前吸附规则恢复；QQ 通知仍可正常显示。

## 非目标

- 不读取或解密微信本地数据库。
- 不注入微信进程。
- 不增加 OCR 依赖。
- 不改变通知显示时长、灵动岛布局或当前版本号。
