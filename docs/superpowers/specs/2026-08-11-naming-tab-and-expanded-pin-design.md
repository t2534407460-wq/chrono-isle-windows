# 取名页签与展开置顶设计

## 目标

将取名助手从独立窗口收回岛屿展开界面的“工具”页签，与网络测速并列；在展开状态提供一个图钉按钮，以三态控制自动折叠与窗口置顶。

## 取名助手

- “工具”页签继续只保留“取名”和“网络测速”两个二级页签。
- 取名页签直接承载原 `NamingWindow` 的输入、生成、候选切换、推荐命名和复制功能；不显示“打开”按钮。
- 移除 `NamingWindow` 及其依赖注入注册、项目项和所有打开独立窗口的调用路径。
- 岛屿和托盘中的“取名”入口均显示岛屿、展开内容并选中取名页签；不会创建额外窗口。
- 原有命名服务、生成规则、错误提示和复制行为保持不变。

## 展开图钉

- 图钉仅在岛屿展开时可见，位于展开内容的顶部操作区。
- 状态不写入设置；窗口收起后恢复“普通展开”。
- 每次点击按以下顺序循环：

  1. 普通展开：中空图钉，使用普通次级前景色；允许鼠标离开计时器和外部窗口激活触发自动折叠。
  2. 保持展开：中空图钉，使用 `Brush.Accent` 高亮；禁止上述自动折叠，但标题点击等手动收起仍有效。
  3. 置顶保持展开：实心图钉，使用 `Brush.Accent` 高亮；同样禁止自动折叠，并让岛屿窗口保持置顶。

- 从第三态再次点击返回普通展开，并撤销窗口置顶。
- 三态在自由、顶部停靠和任务栏停靠位置统一生效；任务栏的现有周期性置顶仅在第三态运行，避免覆盖普通与保持展开状态。
- 图标与高亮颜色都绑定动态资源，因此设置中切换强调色会即时反映，不增加独立颜色选项。

## 实现边界

- 保留现有 `LifeIslandWindow` 作为唯一展开界面和现有 `NamingSuggestionService` 作为唯一命名逻辑来源。
- 不新增抽象层、设置项或第二套命名界面。
- 自动折叠的拦截放在自动触发路径，不阻止用户主动收起或通过现有导航离开岛屿。

## 验收与测试

- UI 契约测试确认：完整取名控件位于 `LifeIslandWindow`，独立命名窗口与其注册不再存在，岛屿和托盘入口都转到岛屿取名页签。
- UI 契约测试确认：展开图钉的三种图标/资源状态、点击顺序、自动折叠阻止条件与任务栏置顶条件均存在。
- 编译 Release 发布物并启动，确认新进程响应；人工确认三个图钉状态、取名生成和各强调色下的图标外观。
