# 对话延迟入库与自然错误提示设计

## 目标

空白“新对话”只作为当前编辑状态存在，不进入最近对话；发送第一条用户消息后才保存会话。聊天界面不再显示内部错误码、字段名或异常详情。

## 会话生命周期

- 启动时若没有历史对话，创建一个仅存在于内存的临时会话。
- 点击“新对话”时切换到新的临时会话，不写入 `chat_sessions`，也不刷新出一条侧边栏记录。
- `LifeDataService.Message` 在保存第一条消息前以 `INSERT OR IGNORE` 创建对应会话，随后按现有规则用第一条用户消息生成标题。
- 保存第一条用户消息后，`LifeViewModel` 刷新最近对话并选中刚持久化的会话。
- `Sessions()` 只返回至少有一条用户消息的会话，因此历史遗留的空白“新对话”会被隐藏，但不会被删除。

## 用户可见错误

- 缺少单个常见字段时显示上下文提示，例如提醒标题缺失时显示“想提醒你什么？”，提醒时间缺失时显示“想在什么时候提醒你？”。
- 规划、解析或本地执行失败时显示简短自然语言，并明确事项没有被修改。
- 内部诊断继续保留在现有日志、状态或异常对象中，不把 `required_fields_missing`、`argument_invalid`、`title`、异常消息等内容写入聊天气泡。

## 验证

- 连续创建多个空白对话，数据库和侧边栏都不增加记录。
- 临时会话保存第一条用户消息后，只新增一条有正确标题的会话。
- 缺信息回复不包含内部错误码或字段名。
- 规划异常回复不包含底层异常详情。
- 完整核心测试、UI 测试、Release 构建和发布重启通过。
