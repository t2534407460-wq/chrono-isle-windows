# 网络测速工具设计

**状态：已确认**
**日期：2026-08-10**

## 目标与边界

在灵动岛的“工具”页新增“网络测速”二级页签。一次由用户主动发起的测速应给出：

- 到一个可用国内测速节点的下载、上传吞吐量和节点 HTTPS 连接延迟；
- 到英雄联盟、抖音、京东、携程、今日头条的 HTTPS 连接延迟；
- 与现有主题和多色彩设置同步的仪表盘动画与操作按钮。

本期不增加定时测速、结果历史、账号、遥测上传、第三方可执行文件或新的设置项。测试只在用户点击按钮后运行；应用不在后台持续消耗流量。

## 第一性原则

吞吐量的定义是“在可控的测试目标与限定时段内传输了多少字节”，因此下载和上传必须向同一个、允许双向测试的测速后端发起请求。平台网页的响应大小、缓存和业务限流不能代表带宽。

平台卡测量的是 HTTPS 请求从发起到收到响应头的耗时，显示文案为“平台连接延迟”，而不是 ICMP Ping 或带宽。平台探测在下载前并行完成，避免带宽饱和把平台延迟测高。

## 测速节点策略

采用 LibreSpeed 的开放协议，但不引入其 .NET 包或外部 CLI。应用使用现有 `HttpClient` 直接请求协议的 `empty.php` 与 `garbage.php`，以最小新增代码完成节点延迟、下载和上传。

内置两个 HTTPS 国内候选节点，并按以下顺序故障切换：

1. 清华大学：`https://iptv.tsinghua.edu.cn/st/`
2. 武汉大学图书馆：`https://www.lib.whu.edu.cn/speedtest/backend/`

每次测速先并行对两个节点各执行两次带随机查询参数的 `empty.php` GET，每个请求 1.5 秒超时；以每个节点的中位数选择延迟最低的成功节点。节点失败、超时或非成功连接均跳过；两个节点都不可用时，停止吞吐量测试并显示“暂时没有可用的国内测速节点，请稍后重试”。不会显示伪造的 `0 Mbps`。

节点地址来自开源 LibreSpeed 清单中的大陆候选；实现前会进行一次轻量实测，发布前的实时节点可用性仍需要单独验收。LibreSpeed 官方明确支持下载、上传、延迟与多节点；其 CLI 也定义了可本地维护的后端清单格式。[LibreSpeed](https://github.com/librespeed/speedtest) [LibreSpeed CLI](https://github.com/librespeed/speedtest-cli) [大陆节点参考](https://github.com/i-abc/Speedtest) [候选清单](https://gist.github.com/xinyangli/e4c06f60911d6d1bc63155e89dabfa6c)

不采用 `speedtest-cli` 的动态 Speedtest.net 节点发现：该项目已归档，且其维护者说明延迟只用于选择服务器而非可靠延迟值；它也不能测量指定平台的连接延迟。[speedtest-cli](https://github.com/sivel/speedtest-cli)

## 测量流程

整个会话由一个取消令牌控制，最长约 20 秒：

1. **选择节点**：显示“正在选择国内节点”，转动仪表盘外环；完成后固定节点延迟卡。
2. **平台探测**：在下载开始前，对以下固定 HTTPS 地址并发执行一次 `GET /favicon.ico`，使用 `ResponseHeadersRead` 计时，单个平台 1.5 秒超时：
   - 英雄联盟：`https://lol.qq.com/favicon.ico`
   - 抖音：`https://www.douyin.com/favicon.ico`
   - 京东：`https://www.jd.com/favicon.ico`
   - 携程：`https://www.ctrip.com/favicon.ico`
   - 今日头条：`https://www.toutiao.com/favicon.ico`
3. **下载**：对已选节点启动四个并发、持续 7 秒的 `garbage.php` 下载流，累计读取的实际字节数；仪表盘和下载卡每 250 毫秒刷新一次瞬时速率。
4. **上传**：向同一节点启动四个并发、持续 7 秒的 `empty.php` POST，复用小型随机缓冲区；仪表盘切换到上传阶段，并按相同节奏刷新。
5. **完成、取消或失败**：最终速率以所有工作流已传输字节除以对应阶段实际耗时计算，单位为 Mbps（十进制）。取消立即中止全部请求，失败卡显示“未测得”，不向用户暴露异常或协议细节。

## 工具页与动画

“工具”面板新增“网络测速”页签，保留现有“取名”页签。网络测速页由以下区域组成：

- 顶部标题与“开始测速／取消测速／重新测速”主按钮；
- 居中的半圆仪表盘：外环和指针只随真实采样速度与当前阶段变化，不播放与数值无关的伪速度；
- 右侧或下方并列的下载、上传、节点延迟三张紧凑卡片；
- 一行五张平台卡，每张卡都显示本地图标、中文名称、连接状态和延迟；超时显示“未测得”。

平台图标作为本地 20px 资源随应用发布，不在测速中临时从网站下载；这样图标加载不会污染延迟数据，也不会因某个平台不可达而破坏布局。

## 主题和多色彩同步

测速页的仪表盘外环、指针、阶段动画、选中页签、平台图标的装饰色和主按钮全部通过动态资源读取 `Brush.Accent` 与 `Brush.AccentSoft`。因此设置页切换翡翠绿、海洋蓝、紫罗兰等多色彩方案时，这些元素会立即同步更新。

现有 `IslandPrimary` 的默认背景是中性色，不能直接满足彩色主按钮要求。只为测速按钮新增一个外观与 `IslandPrimary` 一致、但背景与边框绑定 `Brush.Accent` 的局部样式；不改变“发送”“添加”“打开”等已有按钮。超时与失败仅使用既有 `Brush.Warning`、`Brush.Danger` 作为语义反馈，不引入硬编码主题色。

## 结构与资源释放

新增单例 `NetworkSpeedTestService`，负责节点选择、测量状态、速率采样、取消和结果快照；`LifeIslandWindow` 只订阅快照，在 UI 线程刷新现有 XAML 控件。服务注册到 DI，并在窗口关闭时取消未结束的会话、解除事件订阅。

服务公开可测试的状态快照和节点选择／速率计算逻辑；HTTP 发送器通过最小的内部包装注入，使单元测试不访问真实网络。测速页面不写入 SQLite、不修改现有常态网络遥测，也不影响状态页的百度连通性检测。

## 验收与测试

- 单元测试覆盖：节点中位延迟选择、全部节点失败、下载与上传的 Mbps 计算、取消、平台超时以及不显示异常文本。
- UI 合同测试覆盖：工具二级页签、三项结果、五个“图标＋名称”平台卡、仪表盘动画元素、取消按钮和主题动态资源引用。
- 手动主题检查：在至少两种色彩方案之间切换，确认仪表盘、动画、平台装饰与测速按钮同时变色，而既有工具按钮外观不变。
- 手动联网检查：验证两个国内候选节点至少有一个可用；完成一次测速并确认下载、上传和平台连接延迟均来自真实请求。该检查与构建、单元测试分开报告。
