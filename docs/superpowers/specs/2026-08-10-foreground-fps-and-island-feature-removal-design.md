# 前台应用 FPS 与岛内冗余功能移除设计

## 目标

在折叠状态栏中显示当前前台图形应用的真实呈现帧率；移除设置页中“收纳新的 Windows 通知，并在灵动岛显示 5 秒”和“播放音乐时在折叠岛显示歌曲信息”两项及其运行时入口。

## FPS 数据语义

FPS 表示当前前台进程最近一秒内的应用呈现次数，不使用显示器刷新率、CPU 使用率或界面计时器替代。通过官方 PresentMon 控制台按前台窗口 PID 收集帧事件，并根据最近一秒有效 `MsBetweenPresents` 事件计算速率。

前台窗口属于 ChronoIsle 自身、前台进程没有可采集的呈现事件、PresentMon 无法启动、权限不足，或连续一秒没有新事件时，状态栏显示 `FPS --`。不显示历史进程的数值。

## 架构

新增单一职责的 `ForegroundFpsService`：

- 每 250 毫秒读取当前前台窗口及所属 PID，忽略 ChronoIsle 自身。
- PID 改变时停止旧 PresentMon 子进程，启动只针对新 PID 的 PresentMon 控制台采集。
- 解析标准输出中的帧间隔数据，维护最多一秒的有效样本，发布 `double?` FPS 快照。
- 服务停止或进程退出时取消读取、终止子进程并清空样本。

PresentMon 的发布文件与其许可文件放入应用资产并随 `win-x64` 发布目录复制。不会安装 Windows 服务、不会注入目标进程，也不会请求管理员权限；采集受权限或渲染 API 限制时以 `FPS --` 表示不可用。

`LifeIslandWindow` 订阅该服务，并在现有折叠状态栏的 CPU 与内存指标之间放置 `FpsSummary`。它与现有遥测总开关一致：遥测关闭时不启动采集且隐藏该文本；启用时显示 `FPS <整数>` 或 `FPS --`。

## 移除范围

设置页移除以下两个复选框及其加载、保存代码：

- `ToastInboxEnabled`：停止应用启动、偏好变更后启动 Windows 通知收纳服务；移除岛窗口对该服务的订阅和岛内通知卡片显示入口。
- `MediaAutoTakeover`：删除无效设置项；同时移除折叠岛歌曲摘要、歌曲卡片与右键“显示音乐模式”操作，使媒体会话不再改变折叠岛内容。

为兼容已经写入磁盘的偏好 JSON，历史 `ToastInboxEnabled`、`MediaAutoTakeover` 和 `IslandShowMusicMode` 属性保留在 `LifePreferences` 中，但不再由运行时代码读取来启动或展示上述功能。不会删除已有通知、媒体或测试文件；只切断入口，避免扩大修改范围。

## 测试与验收

- 对 PresentMon 输出解析写纯单元测试：有效帧间隔生成 FPS，非数值/过期样本生成空值。
- 对前台 PID 切换写契约测试：旧采集被取消，新 PID 被传给采集命令，ChronoIsle 自身不会成为采集目标。
- 对状态栏 XAML 和更新链路写契约测试：存在 `FpsSummary`，显示位置位于 CPU 和内存之间，遥测关闭时隐藏，不可用时为 `FPS --`。
- 对移除范围写契约测试：设置页、启动代码和岛窗口不再包含通知收纳或折叠音乐入口；旧偏好字段仍可反序列化。
- 定向测试通过后执行 Release 发布替换。手工验收需在一个会持续呈现的前台图形应用中观察 FPS 随负载变化，并切换到桌面或普通静态应用确认显示为 `FPS --`。

## 非目标

- 不增加 FPS 的独立设置项。
- 不显示 GPU 占用、帧时间图、1% low 或多应用列表。
- 不通过进程注入、屏幕抓帧或刷新率估算 FPS。
