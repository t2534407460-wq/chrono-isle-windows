# 场景驱动的事项 Agent 交互

状态：已修改待测试；设计已实现并替换桌面运行版本，人工验收尚未通过。日期：2026-09-20。

## 本次目标

用户指出 V3 只是把缺参错误包装成固定时间控件；“每天工作时间间隔2小时提醒我站起来活动，除午休时间外”丢失了时间窗口、间隔和排除条件。本次不是增加一个特例控件，而是补齐任务语义、交互规划与实际调度之间的合同。

成功标准：原始条件在计划中可见；未知条件有针对性的可操作控件；修改局部条件保留其他条件；预览的实际时刻与最终调度一致；未支持条件不能悄悄忽略；明确单次操作继续简洁。

## 交互循环

1. 理解：显示目标、已明确条件与仍待决定的事项。
2. 补充：按场景产生问题，每题包含原因、可选方案和自定义入口；字段可依赖前一选项。
3. 预览：显示将创建/修改的事项、完整规则和未来提醒时刻。复杂计划必须确认。
4. 执行：沿用事务、版本验证和幂等回执，展示实际结果。中断或失败保留草稿。

用户可点击补充，也可继续自然语言纠正。点击回答直接修改草稿；不依赖模型重新解释选项。模型不生成任意 XAML、不调用数据库、不决定是否跳过确认。

## 场景与组件

| 场景 | 交互与默认行为 |
| --- | --- |
| 明确单次提醒 | 保留直接创建；歧义时提供日期时间控件与候选建议，可自定义 |
| 时间窗口内间隔提醒 | 执行日、工作时段、间隔、排除时段、首次触发方式、暂停期间计时策略；生成实际时刻预览 |
| 每日多个固定时刻 | 可编辑时刻列表、执行日、开始/结束日期，确认后保存为一个周期事项 |
| 指定工作日 | 区分每天、周一至周五、法定工作日、自选星期；自选使用多选控件 |
| 日程只有开始或时长 | 可填写时长（分钟）或明确结束日期时间；不强迫用户反复计算结束时间 |
| 查询事项 | 快捷范围与自定义起止日期，按依赖显示日期编辑器 |
| 修改已有事项 | 候选身份与时间，修改前后预览；确认前重新验证版本 |
| 多步骤请求 | 保留全部步骤与已填条件，只补缺项；整体预览并原子执行 |
| 暂不支持的条件 | 展示具体未覆盖条件，保持未执行；让用户明确修改条件或取消，不能自动降低要求 |

## 示例完整过程

原话：每天工作时间间隔2小时提醒我站起来活动，除午休时间外。

已知：目标站起来活动，间隔120分钟，限定工作时段，排除午休。
需决定：哪些日子、工作时段、午休时段、第一次何时提醒，以及午休后如何计时。
示例选项只提供建议，不擅自保存为用户偏好。

若用户选择周一至周五、09:00–18:00、排除12:00–13:00、工作开始后满2小时第一次、继续原节奏，则预览11:00、13:00、15:00、17:00。
若选择午休结束重新计时，则预览11:00、15:00、17:00。
时间窗口为左闭右开，午休开始包含在排除范围内，结束时刻恢复活动。结束工作时刻不再提醒。每天重新计算，不把前一天时差带到次日。

## 工程边界

- 扩展草稿语义，不把间隔、范围、排除项塞入一个 timeText。
- 增加场景规划器，负责本地条件提取/覆盖检查、问题说明、字段依赖和计划预览。
- 周期计划作为一个事务命令保存，日内多个时刻属于一个事项，不扩成互不关联的多个顶层待办。
- 同一份确定性日内时刻算法同时用于预览、日历和到期投递。
- 新增独立周期扩展存储，兼容既有每日/每周单时刻记录。保留过去的已验证投递、跳过、重启恢复和幂等行为。
- 审核/编辑重新生成计划并废弃旧确认。复杂日内计划始终确认，不以单条创建为理由绕过核对。
- 旧待补充草稿升级时只重建问题，不因打开会话而执行。
- 旧单时刻管理界面不得覆盖复杂计划的窗口/排除条件；不支持的修改要明确阻止。

## 验证矩阵

- 不同午休范围、执行日、间隔、首次触发和午休后计时策略得到不同预览。
- 原场景不能生成只有一个 time 字段的卡片。
- 完整自然语言与逐题补充得到相同计划。
- 修改一个答案保留其他答案；重启恢复完整计划；旧卡不能执行。
- 到期提醒逐次投递，午休/非执行日/结束日期不触发，重复检查不重复投递。
- 明确单次提醒、日程、候选事项、查询、多步骤保留正常路径。
- 快问/完整对话、深色/浅色、窄宽布局、长选项与滚动检查。
- 模型遗漏间隔、排除条件、未知复杂约束时阻止无声降级。


## 实现对应

| 层 | 主要实现 | 职责 |
| --- | --- | --- |
| 理解 | AssistantDraftInterpreter / AssistantTaskDraft | 保留原话的间隔、窗口、排除、重复和结束条件；最多一次结构修复 |
| 本地规划 | AssistantScenarioPlanner / AssistantDraftCompiler | 检查遗漏条件、生成问题及字段依赖、时长换算、验证并预览实际时刻 |
| 会话 | AssistantDraftRuntime / AssistantDraftStore | 保留局部答案、恢复旧草稿、修订版本、处理不支持的条件与重新描述 |
| 呈现 | AssistantTaskCard / AssistantInputViewModel / LifeViewModel | 时长、时段、日期、多选星期、固定时刻列表、候选项与确认预览 |
| 执行 | AssistantPlanPipeline / CanonicalCommandHandlers | 复杂计划强制确认；事务内保存主事项、周期规则和日内扩展计划 |
| 调度 | ReminderDailySchedule / RecurringReminderData / ReminderService | 日历与提醒共用时刻；队列和重试仍遵守有效时段；传递具体发生时间到横幅 |

新增 assistant_reminder_schedules 表按事项 ID 保存一个日内计划，兼容原有单时刻记录。修改、删除、事务回执和版本检查沿用现有框架。复杂日内计划的全量编辑发生在确认前；已创建复杂计划可以改名称/备注，旧单时刻编辑器不允许覆盖规则，调整规则需重新规划。

在应用休眠或关闭错过多次后，仅补最近一个到期时刻；午休和工作结束后不补发，次日不补前一日。确认卡明确说明此行为。草稿有效期仍为15分钟，已提交答案可恢复，尚未提交的控件内容不保证重启保留。

本轮限定单日内有效窗口，支持以00:00表示当天午夜结束；继续到次日凌晨的跨日窗口仍需分开安排。需要额外条件的请求会继续补充或明确要求调整。模型未表达的复杂条件仍存在理解风险，不能以小样本通过代替人工验收。

## 人工验收入口

1. 发送原场景“每天工作时间间隔2小时提醒我站起来活动，除午休时间外”。应出现执行日、工作/休息时段、首次提醒和午休后计时方式。
2. 选择周一至周五、09:00–18:00、12:00–13:00、先满一个间隔、继续原节奏；核对11:00、13:00、15:00、17:00。确认前应没有新事项，确认后只有一个重复事项。
3. 确认前点击修改或说“改成每隔1小时”，检查其他条件保留、旧确认卡失效。
4. 尝试“每天上午9点和下午3点提醒我喝水”“明天下午三点安排项目评审”“查看事项”；分别检查时刻列表/预览、时长控件、自定义日期范围。
5. 在快问和完整对话中检查滚动、深浅主题、取消与重开会话，再验收实际到时提醒和午休不提醒。
